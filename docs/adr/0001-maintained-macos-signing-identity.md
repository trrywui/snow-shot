# 维护版 macOS 发行包复用固定自签名身份

2026-10-29，与维护者确认：维护版继续服务于自用和从 GitHub Release 下载 DMG 手动覆盖的流程，发行包改用长期固定的自签名证书。ad-hoc 签名把授权身份绑定到构建哈希，覆盖升级可能使旧授权失效；固定证书可使不同构建满足同一签名要求，同时避免引入付费开发者账号和公证发布流程。

证书及私钥长期复用，公开证书指纹和签名要求纳入发行校验；缺失或不匹配时停止构建、打包，不自动换证，也不退回 ad-hoc。私钥保存在维护者钥匙串，不进入仓库、构建清理目录或 Release 附件；更换构建机器须先恢复同一身份。

从现有 ad-hoc 版本迁移时，允许用户重新授权一次。验收须以相同安装位置上的两个不同构建验证权限继承，并验证真实截图及辅助功能访问，不能仅检查系统设置开关。通过后递增维护版本并发布新的 GitHub Release，保留旧版回退；附件仍只有 DMG 和 SHA256。

该方案不等同于 Developer ID 签名或 Apple 公证，不能保证所有 macOS 版本和系统策略下均保留授权。将来若转为面向公众正式分发，应重新评估 Developer ID 和公证；更换身份可能再次需要授权。

同日补充：维护者随后明确要求不要替换本机应用。助手已撤销当时启动的基线安装，原样恢复原应用，测试副本未启动，也未更改系统隐私权限。此后只操作工作区内的构建和发行材料；实际覆盖升级及权限继承验收由维护者手动完成。两个不同应用的签名要求兼容性校验须与真实权限继承验收分别记录，不可把前者表述为后者已通过。
