# 截图交互 CPU 后续排查与方案

日期：2026-10-16。源码基线 3eff464d8。本轮只读分析及既有隔离副本对照，未修改运行时代码、安装版或正式配置，未重新编译。

## 已确认与未确认

前两项优化去掉了放大镜重复装饰绘制、Qt opacity effect 和 RGBA 转换热点，但没有证明解决交互时 40%+ CPU。后续不透明提示、静态底图分离均未得到足够真实交互收益，已撤回。

截图呈现已按屏幕刷新率调度；本机 60 Hz，静止后取消待执行帧。没有证据支持把常驻轮询或“完全没有节流”当作根因。Qt Cocoa 的透明 backing store 仍需局部清理、绘制和缓冲同步；前次把底图移走仍保留了完整 Qt 动态窗口，因此该实验不等于消除这条路径。

旧符号化采样含原生光标协调路径：WindowCursorCoordinator → hoverTarget → NSWindow.windowNumberAtPoint → QApplication::topLevelWidgets。其事件过滤器在 MouseMove、Move、Resize 等事件上安排一次队列刷新，队列内合并不等于按显示帧合并。放大镜自身移动也可能触发额外刷新。
采样混合活动/静止和等待栈，不能把包含该函数的采样数换算成其 CPU 百分比。

固定选区 API 直接更新 selection 并调用 updateOverlayState；真实鼠标还经过指针、放大镜与原生光标维护。因此固定 API 回放有助于比较绘制成本，但无法完整验证实际鼠标体验；旧的混合阶段手动样本也不能用于精确降幅。

## 新增低成本对照：Qt GUI 线程池

本机捆绑的 Qt 6.12.0 源码 qguiapplication.cpp 中存在 QT_NO_GUI_THREADPOOL 开关。qdrawhelper.cpp 会将部分填充拆成线程池任务再等待完成。等待本身不等于 CPU 消耗，是否节省必须实测。

复用 static-backdrop-516bow4b/deploy/snow_shot.app，同一 Release 二进制，SNOW_SHOT_STATIC_BACKDROP 始终为 0；只比较 QT_NO_GUI_THREADPOOL 不设置/设置为 1。两个配置均在私有目录，禁用全局快捷键、自启动。顺序 0/1/1/0/0/1，每阶段 30 次/秒目标、10 秒，全部六轮有效，295–300 次更新。CPU=累计进程 CPU 时间差/实际时长，100% 为一个逻辑核心，无详细日志和并行编译。

| 应用 CPU 中位数 | 默认线程池 | 关闭线程池 | 差值 |
| --- | ---: | ---: | ---: |
| 移动选区 | 42.48% | 39.09% | −3.39 个百分点 |
| 调整选区 | 42.98% | 38.48% | −4.50 个百分点 |

原始应用 CPU：移动默认 42.48/43.19/42.29%，关闭 39.40/39.09/39.00%；调整默认 41.50/42.99/42.98%，关闭 38.48/38.59/37.29%。关闭组每次均小于默认组三次的最低值，但只有三轮，尚不能推广到所有输入和机器。
WindowServer 移动中位数约 41.39%/41.39%，调整约 42.30%/43.19%，无稳定改善证据。应用 RSS 均约 202 MiB，没有稳定内存收益。
此处测试不完整覆盖实际鼠标链路；该开关影响整个应用的部分图像工作，不能据此直接设为正式默认。两个隔离测试进程均已退出。

## 建议顺序

1. 首先针对真实鼠标做定位，并优先优化 macOS 光标协调：记录每秒鼠标事件、系统窗口查询、光标应用、画布/放大镜绘制次数。对同一窗口内不变的光标利用可信事件目标与缓存；仅在窗口归属、层级、模态/菜单、穿透或光标形状变化时重新确认。保持鼠标按下/释放和跨窗口边界及时处理。已有 macos_cursor_tests.cpp 可覆盖光标回归，不能直接删除保护逻辑。
2. 用现有“取色器显示模式 → 始终隐藏”做独立对照，分开观察只移动鼠标与拖动框选。前次仅优化阴影与透明度，没有隔离整个放大镜的窗口移动、放大图和文字绘制成本。若收益显著，可让位置/选区保持 60 Hz，图像或文字采用较低刷新率，并在停下和复制时更新到最新值；具体频率需测试决定。
3. Qt 线程池开关已有小幅收益，作为补充候选保留。正式采用前比较真实鼠标、首次显示延迟、大图绘制和编辑，不把等待栈当作 CPU 归因，也不修改全局系统环境。
4. 允许体验取舍时，试验 45/30 fps 的截图交互省电模式。60→30 只代表最多减半目标绘制次数，不能保证总 CPU 减半；选区坐标及复制结果保持完整精度，松开/复制及时提交最终状态。当前程序已有 60 Hz 合帧，新增普通节流并非全新方向。
5. 若必须保持流畅度并追求大幅下降，再做原生/Core Animation 或 GPU 截图呈现原型：静态截图驻留，遮罩/边框和小放大镜更新，普通选区阶段退出全屏 Qt raster backing store 的反复绘制与同步，进入复杂标注再使用现有编辑器。与上次仅分离底图有实质区别，但工作量大，需验证颜色、DPR、多屏、窗口层级和截图结果；目前没有本机收益保证。

## 验证要求

下一轮真实鼠标测试应明确区分悬停/框选/拖动已有选区，不使用一个固定时间切分混合样本。记录按下/释放标记及实际更新数，A/B 保持分辨率、选区面积、鼠标轨迹/速度接近；分别给出应用和 WindowServer 数据。无日志 CPU 与详细调用栈/区域日志分开采集。

前述方案都没有证据支持保证降到 Snipaste 的 10% 左右。日常全局截图快捷键仍属于原安装版；优化测试不等于已替换日常使用的版本。
