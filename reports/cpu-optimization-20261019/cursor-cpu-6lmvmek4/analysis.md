# 截图交互 CPU：放大镜与 Qt GUI 线程池对照

基线：`3eff464d8`，包含前两次正式优化。系统安装版未修改。
实际使用此前独立部署的静态底图实验二进制，`SNOW_SHOT_STATIC_BACKDROP=0`。
所有测试关闭全局快捷键和自启动，使用独立配置和经 PID 校验的私有 MCP 端点。

## 手动交互

用户在每个副本依次静止、悬停移动、按住拖动、静止、双击复制，并确认外观及复制正常。
隐藏放大镜副本确实看不到放大镜；线程池关闭副本正常显示放大镜，用户确认流畅。

采集进程累计 CPU 时间，每约一秒计算 CPU 增量除以墙钟时间。100% 表示一个逻辑核心。
只在自身截图窗口显示期间，每 50 ms 读取鼠标位置及左键状态，用于划分阶段；
不注入输入、不采集图像。这些样本不是操作系统事件次数。
拖动样本要求按住比例超过 95%、移动距离超过 5；悬停要求首次按下前没有按住且距离超过 5；
静止要求未按住且距离小于 1。边界样本排除。详细规则见 summarize-manual.py。
CPU 测试没有同时编译、调用栈采样或详细绘制日志。

| 单秒 CPU 样本中位数 | 基线 | 隐藏放大镜 | 正常放大镜、关闭 Qt GUI 线程池 |

手动轨迹、速度及选区尺寸不同，不能把表中差值作为精确因果降幅。
隐藏放大镜主要影响悬停，未改善拖动；线程池关闭的拖动信号更显著，值得继续验证。
WindowServer 是共享进程；RSS 不是总内存。完整原始值见 comparison-summary.json、
comparison-rows.json 以及 manual-*-cpu.json、manual-*-pointer.jsonl。

前一轮固定选区 API 30 Hz、六次交替测试也显示线程池关闭有重复的小幅收益：
移动中位数 42.48%→39.09%，调整 42.98%→38.48%。该接口绕过实际鼠标及放大镜路径，
不能与手动绝对 CPU 混用。原始数据在 ../cpu-recheck-knnpht2o/。

## 候选实现（验证中）

Qt 6.12.0 本地源码 qpaintengine_raster.cpp 的 drawImage 对矩形裁剪有直接复制分支；
复杂裁剪区域会走 span rasterizer，并可能调度 GUI 绘图线程池。qdrawhelper.cpp 的
QT_THREAD_PARALLEL_FILLS 会创建任务并等待完成，等待调用栈本身不是 CPU 占比。

候选只对不透明 RGB32、全不透明 Source/SourceOver、无平滑缩放、1x/2x 像素一一对应、
2–128 个矩形的底图重绘逐块调用 drawImage；每块裁剪与调用者裁剪相交并恢复 painter 状态。
其余路径保留原实现。不修改全局线程池、默认刷新率、放大镜或正式配置。
候选补丁 clip-experiment.patch；待正确性及实际 CPU 验证后决定是否保留。

候选运行时代码和新增测试已撤回；补丁及校验值已归档，正式的前两项优化保留。
固定 API 三轮中位数：移动 44.09→42.30%，调整 43.50→42.58%，范围重叠。
手动候选悬停30.57%，拖动74.82%（56.15–92.63%），静止0%。
