# 30 Hz＋BGRA 的精简版验证

起点为 `9359bf30e`；在仅限帧提交 `b7c03b439` 上单独加回 BGRA，
分支为 `codex/screenshot-30hz-bgra`，本轮提交 `bead79761`。
相对起点总共四个文件：两个运行代码文件、两个测试文件。
不带入放大镜缓存、原生透明度或额外性能日志。

## 比较条件

先测完整优化版，再测“限帧＋BGRA”，两版均为 30 Hz、正常放大镜、
默认 Qt GUI 绘图线程池；不记录绘制日志，不采调用栈，采样时不编译。
两版使用相同测试配置、独立数据目录，全局快捷键、自启动、历史持久化、
智能选择和选区过渡动画关闭。正式安装版及配置不更改。

CPU 来自约一秒区间内进程累计 CPU 时间差，100% 表示一个逻辑核心。
只在测试副本全屏截图期间记录指针位置，用来划分移动、拖动和静止阶段。
手动轨迹不完全一致，不能把单轮差值当作精确因果降幅。

日志、原始采样和二进制留在此 Git 忽略目录，不增加源码分支文件。
构建和签名验证通过，相关 CTest 3/3、格式和差异检查通过；本轮实测见下文。

## 完整优化版再次复核

用户要求再测完整优化版以排除上轮不准确。复用相同二进制，SHA256核对
一致，独立数据目录，相关截图/系统配置与上轮一致，30 Hz、正常放大镜、
默认线程池、无绘制日志、无调用栈采样，不修改源码。full30-recheck1
记录到一次完整截图开始和结束，持续32.76秒；用户回复“复核完成”。

仍较小，面积也小于BGRA版378735。WindowServer移动41.41%、框选41.03%。

完整优化版移动比自己上轮高0.47个百分点，框选低3.46个百分点；相对
BGRA上一轮分别低14.19和15.20个百分点。完整→BGRA→完整的顺序结果
显示完整优化版的低占用能够重复，不能简单解释为第一次偶然测低。
但并非严格受控实验，没有锁定轨迹、选区和系统负载，不据此声称精确
降幅或把差值完全归因于放大镜，更不能分别确认缓存/透明度贡献。

因此当前结论保持：完整优化版的收益值得保留；30 Hz＋BGRA尚不能认定为
性能等价替代。若要继续精简，下一步应单独验证macOS放大镜原生透明度，
而非直接删去全部放大镜改动。本轮仅归档复核数据，未新增源码改动。
