# 仅限帧的精简版验证

- 起点：`9359bf30e`，标签 `v1.1.0+up.1.3.0`。
- 分支：`codex/screenshot-30hz-minimal`。
- 只移入 `fb0caf79c` 中的呈现频率上限和必要测试。
- 不包含放大镜装饰缓存、原生透明度、BGRA 和额外绘制日志。
- 完整优化分支保留在 `codex/screenshot-rendering-cpu` / `fb0caf79c`。

## 比较条件

两版均通过进程环境变量 `SNOW_SHOT_CAPTURE_PRESENTATION_FPS=30` 启用 30 Hz，
放大镜正常显示，Qt GUI 绘图线程池正常启用。采样期间不编译、不记录绘制日志、
不进行调用栈采样。两版使用相同的测试配置，但数据目录各自隔离；全局快捷键、
自启动、历史持久化、智能选择、选区过渡动画均关闭。正式安装版和配置未更改。

CPU 根据约一秒内进程累计 CPU 时间差计算，100% 表示一个逻辑核心。仅在测试
副本的全屏截图窗口存在期间记录指针位置，每秒约 20 次，用于区分移动、拖动和
静止。手动轨迹不完全相同，不把单轮差值解释为精确的因果降幅。

此前带绘制日志的采样条件不同，不直接比较绝对 CPU 值。

## 文件范围

最终源码补丁仅包含呈现服务和对应测试两个文件。此目录及原始采样、隔离数据、
二进制、构建日志被 Git 忽略，避免把排查材料带入精简分支。

构建与签名验证通过；相关 CTest 2/2 通过，格式与差异检查通过。
源码已保存为本地提交 `b7c03b439`。

## 2026-10-18 手动对比结果

有效顺序为精简版 `minimal30` → 完整优化版 `full30`。两轮均记录到一次完整
截图开始与结束，用户确认“两轮完成”，未单独描述外观、跟手和复制差异。
配置内容一致，线程池正常启用，均为 30 Hz，均没有绘制日志。正式版保持运行
且空闲，测试前已确认所有编译、链接和旧测试进程退出。

| 单秒区间中位数 | 仅限帧精简版 | 完整优化版 | 精简版减完整优化版 |
| --- | ---: | ---: | ---: |
| 移动鼠标：应用 CPU | 38.49% | 25.63% | +12.86 个百分点 |
| 按住框选：应用 CPU | 44.29% | 30.47% | +13.81 个百分点 |
| 静止：应用 CPU | 0% | 0% | 0 |
| 移动 / 框选 / 静止有效区间数 | 12 / 12 / 10 | 11 / 11 / 12 | — |
| 移动：指针累计路程中位数（逻辑像素 / 区间） | 828.88 | 856.19 | — |
| 框选：指针累计路程中位数（逻辑像素 / 区间） | 349.91 | 380.20 | — |
| 框选：WindowServer CPU | 36.40% | 35.38% | — |

精简版框选 CPU 有效区间范围 36.45–48.21%，完整优化版为 26.55–34.40%。
用首次按下位置估算的选区面积中位数约为 392,294 / 435,515 逻辑像素；完整
优化版并没有更小的移动幅度或面积，但手动轨迹仍不完全一致。整轮进程 RSS
峰值分别约 213.52 / 246.06 MiB，包含不同应用阶段，不等于活动监视器内存
指标，也不用于单独归因某项缓存。

本轮不支持“只保留限帧还能保持相近 CPU”的假设。结合两轮操作幅度接近且
框选有效 CPU 区间分离，放大镜改动和 BGRA 的合并效果值得保留进一步检验；
不能再将其直接视为可忽略。仍只是一次顺序对比，不能给出精确因果降幅，
也不能把差异分别归因于 BGRA、缓存或原生透明度。没有在本轮测试精简版的
默认频率，因此也不能据此量化精简版自身启用 30 Hz 的收益。

若继续追求最小源码差异，下一个候选应是“精简版只加回 BGRA”，以很小的
运行代码改动单独检验像素格式的贡献。此方案尚未实现或测试。当前不替换
正式安装版，不将仅限帧版本认定为性能等价替代。
